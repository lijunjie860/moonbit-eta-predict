# Benchmark protocol

The benchmark suite is generated by `run_benchmark_suite()` and exposed through:

```bash
moon run cmd/main -- benchmark table
```

It contains four deterministic scenarios:

- `stable`: low congestion and no injected measurement spike;
- `noisy`: periodic positive and negative measurement spikes;
- `delayed`: longer observation intervals and lower base speed;
- `congested`: high congestion and a short local speed envelope.

The output reports points, MAE, RMSE, and mean confidence for each case, followed by a point-count-weighted aggregate. The suite is a regression signal for algorithm changes; it is not an external traffic-data validation and should not be interpreted as a production accuracy guarantee.

The benchmark implementation is deterministic because scenario generation uses fixed wave patterns and fixed noise rules. A change to the algorithm, defaults, or scenario definitions should update the measured table in the README only after running the command and reviewing the resulting diff.
